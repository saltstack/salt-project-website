## Salt Releases 3006.30, 3007.17, and 3008.5: Aligning with the Upstream Certifi Trust Store Policy

We're releasing Salt 3006.30, 3007.17, and 3008.5 today following a subsequent administrative update to the Python trust store ecosystem. These are narrow, targeted patch releases — each contains exactly one change on top of the prior release in its line, nothing else.

### What happened

Following the initial mitigation of the eMudhra/emSign certificate authority intermediate key compromise (remediated in `certifi 2026.10.19`), Mozilla issued a progressive trust policy change (`certifi 2026.10.23`). This update completely removed the remaining, uncompromised emSign root certificates from the baseline trust store as part of a proactive cleanup of the CA authority. 

While the critical key vulnerabilities were already fully neutralized in our previous release cycle, we are issuing this immediate follow-up to provide upstream trust policy alignment and prevent friction for infrastructure environments utilizing strict, automated security and compliance scanners.

### How this affects Salt

Salt ships the `certifi` package as its fallback trust store inside our onedir Python runtimes. Whenever Salt or its underlying HTTP dependencies execute secure operations without a explicitly specified custom CA configuration bundle, certificate verification falls back to the embedded store. 

By updating our onedir boundaries to the absolute latest trust standard, downstream compliance platforms can cleanly validate that the local Python environments match current upstream security definitions.

### What we fixed

Each of these three releases contains exactly one change, cherry-picked identically across all three branches:

- Bumped certifi to 2026.10.23 (the floor in requirements/base.txt, and the exact pin in every requirements/static/pkg/* lock file used to build onedir packages).

The bundled pip companion package remains at the fully remediated version 26.2.2 introduced in the last round of builds. No other features, bug fixes, or development branch changes are included in these point releases.

### Upgrade guidance

We recommend upgrading to the applicable version to maintain absolute policy consistency across your environments and to eliminate compliance tracker false positives.

As always, see the full release notes for 3006.30, 3007.17, and 3008.5 for complete changelogs.
